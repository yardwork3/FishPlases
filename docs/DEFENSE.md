# Защита курсовой

## Сценарий демонстрации, 3–5 минут

Подготовка: установите APK на телефон, проверьте интернет и открытие карты. Для показа не используйте единственную важную запись. Сохраните пару учебных мест заранее; не очищайте данные приложения перед показом сохранности после перезапуска.

**0:00–0:35 — цель.** «Рыбные места — личный журнал рыболовных точек. Основные данные хранятся локально, приложение не требует регистрации. Карта помогает выбрать координаты, список позволяет работать с записями без сети». Покажите Новосибирск, перемещение и масштабирование, атрибуцию OSM.

**0:35–1:35 — создание.** Удерживайте точку у воды. Сначала попробуйте сохранить пустое название, покажите проверку. Введите «Заводь у моста», «Окунь, щука», оценку 4, заметку «Подход со стороны тропы», включите избранное. Сохраните и нажмите метку. Покажите заполненную карточку.

**1:35–2:20 — изменение.** Откройте редактирование, измените заметку и оценку. Сохраните. Покажите фильтр «Избранные» и тот же объект в списке. Скажите: «Изменения поступают из Room через Flow, карту не нужно обновлять вручную».

**2:20–3:00 — сохранность и отсутствие сети.** Закройте приложение и откройте снова. Покажите, что запись осталась. Отключите интернет, откройте список и карточку. «Карта зависит от тайлов в интернете. Локальные данные доступны независимо от них». Верните интернет.

**3:00–3:40 — геолокация и удаление.** Нажмите кнопку местоположения. При первом запросе можно показать отказ: работа продолжается. Если разрешение уже выдано, покажите центрирование; не тратьте больше 15 секунд на ожидание GPS. Нажмите удаление учебной записи, сначала отмените, затем подтвердите.

**3:40–4:40 — код.** Покажите `FishingSpot`, DAO и `SpotsViewModel.save()`. Объясните архитектуру, nullable-оценку, авто-ID, блокировку повторного сохранения. Покажите отчёт JVM-тестов и честно укажите, какие проверки на телефоне выполнены лично.

## Короткое объяснение архитектуры

1. **Compose** отображает `SpotsState` и передаёт действия во ViewModel. Карта встроена через `AndroidView`, поскольку MapLibre использует обычный Android `MapView`.
2. **ViewModel** живёт дольше пересоздания Activity при повороте экрана. В ней находятся форма, фильтр, выбранная карточка и флаг выполняющейся операции. `StateFlow` сообщает интерфейсу об изменении состояния.
3. **Репозиторий** проверяет название, координаты, оценку, категорию и вызывает DAO. Здесь обрезаются пробелы по краям текстов. Проверки не зависят от конкретного экрана.
4. **Room/DAO** хранит таблицу SQLite и выполняет insert/update/delete. Наблюдаемый `Flow<List<FishingSpot>>` обновляется после изменения таблицы. Запись идёт в coroutine через suspend-функции; основной поток не блокируется.

Фильтр избранного вычисляется из общего списка. Запись, скрытая фильтром, не удалена из базы. Координаты меняются только при выборе новой точки; форма редактирования меняет сведения о существующем месте.

## Модель

| Поле | Тип | Назначение |
|---|---|---|
| id | Long | Автоматический первичный ключ, 0 у ещё не сохранённой записи |
| name | String | Обязательное непустое название |
| latitude / longitude | Double | Координаты в градусах, диапазоны −90…90 / −180…180 |
| fishTypes | String | Произвольный текст, пустая строка допустима |
| biteRating | Int? | 1–5 либо NULL, отсутствие оценки не равно нулю |
| note | String | Заметка, пустая строка допустима |
| isFavorite | Boolean | Избранное |
| category | String | Сейчас только fishing; резерв расширения модели |
| createdAt | Long | Время создания в миллисекундах Unix, сохраняется при редактировании |

## Возможные вопросы преподавателя

**Почему не osmdroid?** Его репозиторий архивирован. Для нового проекта выбран развиваемый MapLibre; источник карты — OSM. Обязательного платного ключа нет.

**Как исключены дубликаты при быстрых нажатиях?** ViewModel синхронно выставляет `busy` до запуска coroutine. Следующий вызов игнорируется, кнопки на время операции отключены. При ошибке флаг сбрасывается, заполненная форма остаётся.

**Что происходит при отказе в геолокации?** Показывается русское сообщение. Карта и ручное добавление доступны; начальная позиция — Новосибирск. Фонового разрешения нет.

**Где хранятся данные?** В приватной SQLite-базе `fishing-spots.db` внутри приложения. В Android Studio можно использовать App Inspection → Database Inspector в запущенной debug-сборке. Внешние серверы получают только запросы тайлов, не карточки мест.

**Почему нет офлайн-карты?** Кеш не гарантирует доступность района без сети. Офлайн-загрузка с публичного тайлового сервера OSM запрещена. Поэтому офлайн-сценарий реализован через список Room.

**Как развивать модель?** Для новых полей нужна новая версия Room, явная миграция и её проверка. Для охоты/грибов можно использовать category, но сначала определить формы и фильтры. В MVP эти разделы не включены.

**Какие ограничения?** Один телефон, без синхронизации и экспорта; при удалении приложения база теряется. Несохранённая форма переживает поворот, но не гарантирует восстановление после уничтожения процесса. Работу на конкретном телефоне нужно проверить перед защитой.
